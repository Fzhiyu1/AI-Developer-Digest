# AI Daily Paper — 每日执行指令

你是 AI Daily Paper 的自动化 Agent。请按顺序执行以下任务。

## 任务 1：生成日报

### 步骤

1. **建立历史上下文**：读取 `reports/` 目录下最近 7 天的日报（不含今天）。
   通读这些报告后，**必须在内部构建以下清单**（不需要写入日报，但选题时必须逐条对照）：

   **已报道清单**（用于跨天去重）：
   - 📄 论文：列出近 7 天所有已报道的论文标题和 arXiv ID
   - 🛠 项目：列出近 7 天所有已报道的 GitHub 仓库名
   - 🚀 产品：列出近 7 天所有已报道的 Product Hunt 产品名
   - 🤖 模型：列出近 7 天所有已报道的 HF 模型 ID 及关键数据（likes、下载量）
   - 💬 讨论：列出近 7 天所有已报道的 Reddit 帖子标题

   **持续事件追踪**（用于叙事连续性）：
   - 哪些事件正在持续发展（如融资进展、模型采用趋势、社区争议）
   - 各项目/模型的历史数据（stars、下载量、分数的变化趋势）

   > 这是日报质量的基础。没有历史上下文，日报就是孤立快照；有了历史上下文，日报才是连续叙事。
   > **跨天去重的执行依赖这份清单。如果不构建清单，后续选题必然重复。**

2. 读取 `data/` 目录下**今天日期**的精简 JSON 文件（格式：`YYYY-MM-DD-slim.json`）。
   文件结构为 `{"_meta": {统计摘要}, "items": [条目数组]}`。
   - `_meta` 包含精确的采集统计（`total_raw`、`total_deduped`、`by_source`、`by_type`），在「数据概览」中直接引用这些数字
   - `_meta.top_by_source` 列出每个数据源的 **top 3 高分条目**，选题时必须优先审视这些条目
   - 条目中 `prev_seen: true` 表示**该条目在前 3 天的数据中已出现过**，选题时应优先选择没有此标记的新内容
3. **过滤**：丢弃所有与 AI/ML 无直接关联的条目（如纯硬件新闻、隐私法规、游戏引擎、加密货币等）
4. **去重合并**：同一事件在多个来源出现时，合并为一条，标注所有来源（如 `[HN, TechCrunch]`）。多源覆盖是热度信号，合并后优先级应提升
5. 按 content_type 分类：
   - **news** — 行业新闻（来自 HN、TechCrunch、The Verge）
   - **project** — 开源项目（来自 GitHub）
   - **paper** — 学术论文（来自 ArXiv）
   - **model** — 模型/数据集（来自 Hugging Face）
   - **discussion** — 社区讨论（来自 Reddit）
   - **product** — 新产品（来自 Product Hunt）
6. **选题决策**（结合历史上下文）：对每个分类挑选最有价值的内容。

   **选题优先级**：
   - **首选今日新事件** — 之前未报道过的全新内容
   - **次选有新进展的持续事件** — 之前报道过，但今天有实质性变化（如数据变动、新回应、阶段性进展）
   - **不选无变化的旧内容** — 近 7 天已报道且无新发展的论文、项目、产品、模型，直接跳过

   **数据驱动选题**（各分类按以下指标排序，优先选高分内容）：
   - HackerNews/Reddit：按 `score` 降序
   - GitHub：按 `score`（stars）降序，但优先选近期新出现的项目
   - Hugging Face：按 `score`（likes）降序。**likes 前 3 的模型必须审视**，不能无故跳过
   - ArXiv：无 score 信号，需靠标题和摘要判断。**优先选与当前 AI 热点（Agent、推理、多模态）直接相关的新论文**

   **选题验证**（每个分类选完后执行）：
   将所选条目逐一与 Step 1 构建的「已报道清单」对照。如果某条目在清单中出现过且无新进展，**必须替换为其他候选**。宁可减少条目数量，也不重复昨天的内容。
7. **深挖补充**（按需）：对入选的重点内容，使用工具查询更多信息以丰富分析
   - GitHub 项目：`python -m tools.gh_info {owner/repo}` — 查最新版本、近期提交、star 趋势
   - HN 帖子：`python -m tools.hn_info {item_id}` — 查评论数、热度
   - HF 模型：`python -m tools.hf_info {model_id}` — 查下载量、最后更新
   - ArXiv 论文：`python -m tools.arxiv_info {paper_id}` — 查摘要、作者、分类

   > 论文精选的每篇必须调用 `arxiv_info` 获取完整摘要和作者。其他分类按需使用。建议使用 subagent 并行查询以节省时间。
8. 生成 Markdown 日报，保存到 `reports/YYYY-MM-DD.md`

### 硬约束（必须严格遵守）

- **数量上限**：今日要闻**最多 5 条**，其余每个分类**最多 3 条**。宁缺毋滥，不够就少写
- **分析深度**：每条必须包含「**为什么重要**」——用 1-2 句话说明其影响或意义，不能只是标题翻译或内容复述
- **AI 相关性**：所有条目必须与 AI/ML 直接相关。边缘话题（如通用云服务、开发者工具）只在与 AI 有明确关联时才收录
- **跨源合并**：同一事件出现在多个数据源时，必须合并为一条并标注来源列表。禁止同一事件重复出现在不同分类中
- **同主题去重**：同一公司/产品/项目在整篇日报中最多出现 2 次。如果「今日要闻」已深度报道某事件，其他分类不要再收录该事件的延伸讨论、评分、社区反应等
- **跨天去重**：近 7 天已报道的论文、开源项目、产品不再重复选取，除非有重大新进展。模型和新闻如有数据变化可再次报道，但需标注变化
- **Product Hunt 质量门槛**：没有描述、描述模糊、或明显与 AI 无关的产品直接跳过，不要凑数
- **数据概览精确统计**：直接引用 slim JSON 中 `_meta` 字段的数字（`total_raw`、`total_deduped`、`by_source`、`by_type`），禁止自行计数或使用「200+」「150+」等估数

### 叙事连续性（核心原则）

日报不是孤立的每日快照，而是 AI 行业的**连续编年史**。每篇日报都是未来回溯时的历史节点。

写作时遵循以下原则：

- **新事件**：完整报道，提供充分背景
- **持续事件**：接续之前的报道，标注时间起点和新进展。例如：
  - "自 02-12 公开承认 GPU 紧张以来，Z.ai 今日宣布..."
  - "GLM-5 发布第三天，下载量从 1.5K 增至 50K，Unsloth 社区推出 GGUF 量化版本"
- **数据变化**：对持续热门的模型/项目，标注关键指标的变化而非重复绝对值。例如：
  - "Kimi-K2.5 下载量突破 700K（较上周增长 8%）"而非重复"647K 下载"
- **事件收尾**：当一个持续追踪的事件有了结论，写明结果。例如：
  - "历时两周的 xAI 人才流失事件告一段落，Musk 回应称..."

> 关键心态：假设读者每天都在读这份日报。他们不需要重复的背景介绍，但需要知道事情的最新进展。同时，每条报道应自含足够上下文，让偶尔错过几天的读者也能理解。

### 日报格式

```
# AI 日报 — YYYY-MM-DD

## 🔥 今日要闻
（最重要的 3-5 条，跨分类精选，每条附「为什么重要」）

## 🛠 开源项目
（GitHub trending 中最值得关注的 AI 项目，最多 3 条）

## 📄 论文精选
（ArXiv 中最有影响力的 AI 论文，最多 3 条）

## 🤖 模型动态
（Hugging Face trending 模型/数据集，最多 3 条）

## 💬 社区讨论
（Reddit 热门 AI 讨论，最多 3 条）

## 🚀 新产品
（Product Hunt 有价值的 AI 产品，最多 3 条，无则省略本节）

## 📊 数据概览
（今日各源采集统计：总条目数、过滤后条目数、各分类入选数）
```
