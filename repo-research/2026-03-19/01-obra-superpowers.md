# obra/superpowers 研究

- 仓库：<https://github.com/obra/superpowers>
- 定位：面向 AI coding agent 的“技能框架 + 软件开发方法论”
- 今日信号：依然是 GitHub 热门里最有代表性的 agent 工程流项目之一

## 它是什么
从仓库首页描述看，Superpowers 不是单个插件，而是一套完整的 agent 开发工作流：
- 先通过对话澄清真实需求
- 产出可读、可确认的 spec
- 再拆成可执行计划
- 随后由 subagent 按任务推进
- 配合 review、TDD、debugging、worktree 等 skills 自动触发

它卖的不是“更强模型”，而是“更不容易跑偏的工程流程”。

## 为什么今天还值得关注
今天日报里一个核心主题是：**AI 一旦真正开始做事，控制它比唤醒它更难。**

Superpowers 之所以持续火，不只是 star 多，而是它非常贴合这个主题：
1. **把 agent 的自由度收进流程里**：先 spec、再 plan、再执行，比直接让模型开写更可控。
2. **把高手经验做成可复用技能**：把 prompt 经验沉淀成系统化方法，而不是散落在推特线程或个人博客里。
3. **天然适配多种 coding agent 生态**：Claude、Cursor、Codex、OpenCode、Gemini 都给出了安装路径，传播效率很高。

## 对开发者的实际意义
- 说明 AI 编程已经进入“流程工程”阶段，而不是单纯比模型答题能力。
- 团队未来的护城河，越来越像：谁能先把 spec / plan / review / subagent orchestration 标准化。
- 这类项目会继续催生“AI 原生工程管理层”——介于 IDE、任务管理、代码审查和 agent runtime 之间的新基础设施。

## 风险 / 局限
- 方法论完整，意味着学习成本和采用门槛也更高。
- 对轻量、小改动任务，过重流程可能拖慢效率。
- 整体体验仍然依赖底层 agent 的稳定性、工具质量和上下文管理能力。

## 我的判断
`superpowers` 火的根本原因，是它回答了一个真正大的问题：
**怎么把 LLM 从“会写代码”变成“能参与工程协作”。**

如果说 2025 年大家在卷“AI 能不能写代码”，那 2026 年更像是在卷：
**AI 能不能按工程纪律把事做完。**
