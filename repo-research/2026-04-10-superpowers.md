## 📋 项目概述

Superpowers 是一个完整的软件开发工作流框架，专为 AI 编码代理设计。它不是一个简单的工具集，而是一套系统化的开发方法论，通过可组合的"技能"（Skills）和初始指令，确保 AI 代理能够遵循最佳实践进行软件开发。

该项目由 Jesse Vincent 和 Prime Radiant 团队开发，已成为 AI 辅助编程领域最受欢迎的框架之一。

---

## 🎯 核心理念

Superpowers 的核心思想是：**AI 代理需要结构化的工作流，而不是自由发挥**。

传统的 AI 编码助手往往直接开始写代码，缺乏规划和验证。Superpowers 通过强制性工作流解决了这个问题：

1. **先理解需求** - 通过苏格拉底式提问明确用户真正想要什么
2. **设计先行** - 生成可读的设计文档，分段展示供用户审核
3. **详细计划** - 将工作分解为 2-5 分钟的小任务，每个任务包含完整代码和验证步骤
4. **测试驱动** - 强制执行 RED-GREEN-REFACTOR 循环
5. **持续审查** - 在任务间自动进行代码审查

## 🛠️ 核心技能系统

Superpowers 提供了一套完整的技能库，每个技能都是一个独立的工作流模块：

### 开发流程技能

| 技能名称 | 触发时机 | 作用 |
|---------|---------|------|
| **brainstorming** | 编码前 | 通过提问细化需求，探索替代方案，生成设计文档 |
| **using-git-worktrees** | 设计批准后 | 创建隔离的工作空间和新分支，运行项目设置 |
| **writing-plans** | 有设计文档时 | 将工作分解为小任务，每个任务 2-5 分钟 |
| **subagent-driven-development** | 有计划时 | 为每个任务派发新的子代理，两阶段审查（规范合规 + 代码质量） |
| **executing-plans** | 有计划时 | 批量执行任务，设置人工检查点 |
| **test-driven-development** | 实现期间 | 强制 TDD：写失败测试 → 看它失败 → 写最小代码 → 看它通过 → 提交 |
| **requesting-code-review** | 任务间 | 根据计划审查代码，按严重性报告问题 |
| **finishing-a-development-branch** | 任务完成时 | 验证测试，提供选项（合并/PR/保留/丢弃），清理工作树 |

### 调试与协作技能

## 🏗️ 技术架构

### 技能触发机制

Superpowers 的技能是**强制性工作流，而非建议**。代理在执行任何任务前都会检查相关技能：

```
用户请求 → 检查相关技能 → 自动触发工作流 → 执行任务
```

这种机制确保了一致性和可预测性。

### 子代理驱动开发（SDD）

Superpowers 的创新之处在于 **subagent-driven-development**：

1. 为每个小任务启动一个全新的子代理
2. 子代理只看到任务规范，不受主会话上下文污染
3. 两阶段审查：
   - 第一阶段：检查是否符合规范
   - 第二阶段：检查代码质量
4. 快速迭代，避免上下文窗口膨胀

这种方法类似于人类团队中的任务分配，每个"工程师"专注于自己的小任务。

## 💡 核心设计原则

Superpowers 强调四个核心原则：

1. **测试驱动开发（TDD）** - 先写测试，始终如此
2. **系统化优于临时** - 流程优于猜测
3. **降低复杂性** - 简单性是首要目标
4. **证据优于声明** - 验证后再宣布成功

这些原则通过技能系统强制执行，而不是依赖 AI 的"自觉性"。

## 🎯 使用场景

### 适合的场景

1. **复杂功能开发** - 需要多步骤规划和实现的功能
2. **重构项目** - 需要系统化方法避免破坏现有功能
3. **团队协作** - 确保 AI 生成的代码符合团队标准
4. **学习最佳实践** - 通过观察 AI 遵循的流程学习软件工程

### 不太适合的场景

1. **快速原型** - 如果需要快速试错，严格的流程可能过于繁重
2. **简单修复** - 一行代码的修改不需要完整的工作流
3. **探索性编程** - 当你还不确定要做什么时，brainstorming 可能限制创造力

## 🚀 创新点与优势

### 1. 强制性工作流

大多数 AI 编码工具依赖提示词引导，但 AI 经常"忘记"或"跳过"步骤。Superpowers 通过技能系统**强制执行**工作流，确保一致性。

### 2. 子代理架构

传统的 AI 编码会话会随着时间推移变得混乱，上下文窗口充满无关信息。Superpowers 的子代理方法：
- 保持每个任务的上下文清晰
- 避免上下文窗口膨胀
- 提高并行处理能力

### 3. 两阶段代码审查

自动化的两阶段审查（规范合规 + 代码质量）模拟了人类团队的审查流程，捕获了 AI 常犯的错误。

### 4. Git Worktrees 集成

使用 Git worktrees 而不是简单的分支切换，允许：
- 并行开发多个功能
- 隔离的测试环境
- 更安全的实验

### 5. 可扩展性

开发者可以创建自定义技能，遵循 `writing-skills` 技能中的指南。这使得 Superpowers 可以适应不同团队的工作流。
